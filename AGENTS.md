## Product

- No manual shared-URL input in the popup. Choose a video with “Выбрать для всех” to share its page URL and descriptor together. The current shared URL remains read-only; viewing-tab focus/transfer actions remain available by context.
- While popup is open, an absent/closed viewing tab is automatically assigned to the active tab only when its origin/path matches the known shared URL. Background revalidates the current room, URL and absence of a live bound tab inside the serialized binding operation; never steal an existing live binding. This is an authorized exception to explicit-only rebinding, including after browser restart.
- Viewing-page equality uses origin + pathname, ignoring query parameters and hash, consistently for navigation, wrong-page readiness and the return-to-viewing-page action. Navigation still uses the full shared URL; different query-selected content at the same path is not distinguished by this page check.
- “Открыть страницу просмотра” appears when the existing bound tab has a different URL. Background resolves the current shared URL and navigates only that bound tab; no rebind, new tab, room source change or reload of an already-matching URL. Closed/unbound tabs require explicit binding instead.

- Watch Together synchronizes local HTML video players between users through Trystero rooms; media itself is not streamed between participants.
- The creator remains administrator and alone can remove participants. All participants can choose the shared URL/video, control playback, and share invitations.
- The creator coordinates command ordering and shared time without extra playback privileges. Prioritize synchronized playback; do not promise nanosecond precision in browsers.

## Architecture

- Chrome MV3, Plasmo 0.90.5, React 18, TypeScript. Chrome 116+ is required for runtime.getContexts.
- popup.tsx is disposable UI and diagnostics; never own room connections there.
- background.ts routes messages and lazily creates the WEB_RTC offscreen document. Concurrent creation is serialized; worker restart discovers the existing context.
- tabs/offscreen.ts produces tabs/offscreen.html and owns Trystero through lib/room.ts. background.ts restores saved sessions on startup/install and uses a one-minute alarm to recover a lost offscreen document. Popup closure and worker suspension do not own the transport lifetime.
- Trystero is pinned to 0.26.0, using default public Nostr signaling and STUN. No TURN fallback is configured: restricted networks may fail. Never embed private TURN credentials; a future managed TURN integration needs a credential service. yarn.lock is the dependency lockfile; use yarn install for dependency resolution.
- lib/room-protocol.ts defines wtg2 invitations containing room ID, secret and creator public key. Old wtg1 invitations are intentionally incompatible. Treat the whole invitation as an access secret.
- lib/identity.ts uses persistent ECDSA P-256 keys. Nonce proofs bind room ID and both transport IDs; accept each challenge only once within its expiry. Verify the admin public key from the invitation, not a claimed sender/admin flag. lib/room.ts binds authenticated keys to live Peer IDs, serializes async state changes, and limits/deduplicates messages.
- lib/membership.ts defines signed revisioned allow/block policies persisted per room. lib/room.ts verifies creator signatures and rejects policy rollback. Authentication proves key ownership; admission is a separate check. Only admitted peers receive shared snapshots; roster keys must match the current policy revision. Future mesh control handlers must pass canAcceptMemberCommand with authenticated key, roster membership and coordinator readiness.
- Admin removal blocks the stable key, closes the removed client's active session/autorejoin and broadcasts the signed policy. After the first removal, previously unknown keys require explicit admin approval (fresh profiles cannot autojoin with the old invitation). Admin can approve pending peers or readmit a blocked key. A readmitted user manually joins using the existing invitation. Limits: 128 allowed and 128 blocked keys per policy. Room membership does not provide anonymity-resistant identity or media confidentiality: custom clients may retain already-known invitation secrets; application commands are admission-gated.
- Room protocol uses wire version 5 and appId wtg-watch-together-v5 for scheduled playback. Invitations remain wtg2; all participants must update. Older v1 vaults gain an empty policies list through an additive migration, preserving keys and sessions; absent sourceRevision means revision 0. Shared control is optional for older saved sessions and discarded on coordinator restart; playback resumes only through a new explicit command.
- lib/persistence.ts validates version-1 local vaults: identity, active session and signed termination certificates. Absent storage initializes a vault; unknown schemas or corrupt keys stop recovery without replacing identity. Future schema changes require explicit migration. All storage goes through background; offscreen uses runtime messages only. Only the exact offscreen URL may read/write the vault; local storage access is restricted to trusted extension contexts.
- Leaving clears the active saved session, preserving keys. Ending requires the creator's key and persists a signed certificate before transmission. Archived rooms keep lightweight Trystero responders that relay certificates to returning peers, also after restart. Offline users learn termination only when a certificate holder is online; no server provides durable delivery.
- Guest recovery hides saved room details until an authenticated admin snapshot arrives. Missing admin means waiting, never host election. Reconnect rebuilds back off from 30s to 5min; failed transport creation is retried by the recovery alarm. Restored playback state starts paused; common playback commands require current admission and coordinator readiness.
- components/room-panel.tsx polls room state and captures the selected video's initial state on creation. It owns one participant/readiness list, invitations and room actions. components/source-controls.tsx changes the shared URL and conditionally offers focus/transfer based on the active tab and session viewer. VideoPicker separates local binding from shared source selection. Native player controls are the only playback controls; popup shows timeline/clock information under diagnostics, not duplicate play/pause/seek/rate buttons.
- lib/playback.ts owns PlaybackSession in offscreen: every request carries source revision, coordinator epoch and commandId; the coordinator deduplicates and assigns sequence. Only authenticated, admitted peers can send playback traffic. Guests request a canonical state on sequence gaps. Full snapshots recover to the latest timeline rather than replaying obsolete intermediate commands.
- Playback clocks use performance.timeOrigin + performance.now(), three initial ping/pong samples and rolling minimum-RTT estimates refreshed every 10s. Prepare/seek acknowledgements wait up to 5s, then the timeline starts with 400–3000ms lead based on measured delay/uncertainty. Missing/late players catch up when locally available. Pause cancels preparation without waiting for the barrier. Clock estimates do not guarantee rendered-frame simultaneity.
- lib/player-sync.ts controls the selected local video: schedule executeAt minus local clock offset, recheck early timer wakeups, calculate late target position, suppress expected remote media events and debounce native seeked by 150ms. Native play/pause/seek/rate actions are common requests; volume/mute remain local. Support is finite-duration HTML videos at 0.25–4x. Preparation snapshots do not repeat an already-performed seek for the same preparation ID.
- Coordinator republishes canonical playback state every 2s. PlayerSync checks drift every 250ms after command execution: deadband 80ms (increased for clock uncertainty up to 300ms), proportional speed adjustment capped at ±5% of the shared base rate, hard seek from 800ms, 1s seek cooldown. Restores base speed in deadband; automatic changes never become shared rate/seek requests. Buffering reports loading and catches up when data returns without a group pause. Pending native requests/seeking, preparation, future commands and paused/blocked local players are not pulled toward an obsolete timeline. `[WTG sync]` debug logs expose drift/rate/correction; rendered-frame accuracy still requires device/network measurements.
- Local media events go through background's forwardPlaybackEvent; require the currently bound tab AND frame, roomId and revision. Offscreen playback projection contains no invitation/key. Detach, transfer, source change and coordinator loss suspend/cancel the previous player's pending timers. Autoplay rejection reports blocked and adds a local permission button; play() must be called directly inside that user gesture, not after a runtime/network round-trip.
- Debounced manual seeks survive ordinary playback/readiness refreshes: validate room, source revision, coordinator epoch and video identity, never context object identity. Consecutive seeks coalesce to the latest position; detach or replacement invalidates pending seeks.
- Content-script console diagnostics use the `[WTG seek]` prefix for captured seeked events, echo suppression, debounce and handoff to background. Handoff does not confirm coordinator acceptance or delivery to peers. Never log invitations, keys or media URLs.
- lib/source.ts validates HTTP(S) URLs (without embedded credentials), source changes and readiness. Only the coordinator commits source changes, checks expectedRevision and increments persisted sourceRevision. Duplicate command IDs do not increment twice; stale requests/snapshots/readiness cannot replace the current source. Guest requests require current admission and coordinator readiness.
- lib/source-viewer.ts manages one user-bound viewing tab per room/profile; it never creates tabs. On successful create/join, background binds the tab captured at that action. Source updates navigate only that tab and do not reload an already-matching URL. Switching the active tab never reassigns viewing ownership. Offscreen publishes roomId/readiness/shared state through the trusted source-state message.
- “Назначить эту вкладку для просмотра” explicitly binds/transfers viewing to the current tab; “Открыть мою вкладку просмотра” only activates the existing tab/window and never creates/navigates/rebinds. Closed or missing tabs remain unavailable even on a new source revision until explicit rebinding. Leaving detaches ownership without closing the tab. Tab ownership/overrides live in storage.session; worker restart retains user-approved bindings (boundByUser flag). Chrome restart requires explicit binding again; legacy auto-created viewers are discarded as bindings and left open.
- source-watch wakes readiness polling on an already-loaded newly bound top frame; navigation completion and the arriving content script handle page loading. Binding failures must not silently fall back to another active tab.
- Viewer source binding uses an unambiguous selector/shadow path. Shared matching tolerates browser-local blob URLs and session query tokens on the same resource/frame path, but rejects ambiguous targets and incompatible known durations. On binding, store a local descriptor so subsequent local snapshots do not deselect a remote blob source. Local recovery/manual overrides retain strict source checks. Overrides are scoped to room/source revision. Only the managed top frame polls readiness every 2s; other pages send a single load notification. Bindings do not emit new shared commands.
- lib/group-status.ts and components/group-player-status.tsx provide the single group binding summary: current-source acknowledgements give X of N bound, with per-member reasons. Only all current members bound and ready produces green; missing, stale, disconnected, loading or blocked reports cannot produce all-ready. This confirms player bindings, not frame-perfect playback.
- Cards remain neutral. “Выбор группы” means only the shared descriptor; “Привязан у тебя” requires the content script's roomBinding acknowledgement for the current room/revision/video, not matching selector or local selection alone. Keep these separate from global all-ready. “Выбрать для всех” changes the shared source; “Это мой плеер” only maps the local player and appears when shared video exists but local confirmation is missing. Pending requests wait for a newer confirmed source revision (15s timeout).
- Normal popup shows room, one group readiness list and current viewing source. Actions and forms are directly visible when applicable: never put room/member actions, source editing, video selection or transfer behind disclosure panels. Only diagnostics use collapsible details. Invitation text appears only after clipboard failure; ending the room requires confirmation. Runtime, timing, inaccessible-frame and selector details belong in collapsed diagnostics. Show the authoritative shared selector/revision once, separate from local card selectors; include shadow-root selectors and frame URL context. Showing a selector never implies successful binding.
- Source readiness means page loaded, player found, metadata/data available and requested position seekable. Actual playback reports separately distinguish ready/loading/blocked/missing/error. New bindings pause local video; source selection alone never starts playback.
- RoomView.ready gates room details: the creator has authoritative local state immediately; guests become ready only after a validated admin snapshot, and retry resets readiness. Do not use peer discovery or participant count as a readiness signal. components/loading-status.tsx provides the shared loading indicator; errors/retry/leave remain accessible while joining.
- contents/video.ts owns per-frame video discovery, selection and rebinding. Discovery traverses open shadow roots; snapshots refresh while popup is open (2s polling). A 500ms watchdog checks detached selections even with the popup closed, resolving only when disconnected. Rebind only a unique descriptor match, retain local strict checks versus shared room matching, then refresh the canonical timeline. PlayerSync logs attachment and seeking/seeked; seeking is diagnostic only, seeked sends the settled position.
- lib/bindings.ts stores up to 50 local page bindings separately from room state. Save position at most every 2s during playback and on pause/seek/rate changes. Resolve current frame topology by URL after reload, never persist tabId/frameId; duplicate page tabs or frame candidates require manual selection. Content retries restore for up to a minute, pauses the player and restores finite-media position when metadata is ready. Blob-source changes, live media and unavailable players may require manual selection.
- lib/video-dom.ts builds unique selectors within each Document/ShadowRoot and verifies source/duration during resolution. lib/video.ts defines descriptors and snapshots. Frame paths currently contain ancestor-frame URLs, with tabId/frameId used for live routing; repeated identical frame URLs require explicit selection rather than assuming identity across users.
- components/video-picker.tsx displays videos across accessible frames, metadata/posters and selection controls. Selecting in one frame clears other frame selections; Escape cancels picking across the tab. Closed shadow roots cannot be inspected or reliably detected and must not be presented as supported.
- lib/messages.ts defines validated local messages and typed replies. Every DOM route uses explicit tabId and frameId. Content scripts may route only to their own frame.
- Transport, room state and future sync modules go under lib/ and are owned by offscreen; DOM logic stays in content scripts. Offscreen uses chrome.runtime only; tab operations go through background.
- Permissions: offscreen, activeTab, webNavigation (frame topology), storage, alarms and HTTP(S) host access. No scripting/tabs permission is needed. Chrome internal pages, Web Store and inaccessible frames are unsupported. Refresh existing tabs after extension reload to attach content scripts.
